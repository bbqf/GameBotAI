# Data Model: Duplicate Queues

No new entities and no schema changes. This feature composes existing entities:

## ExecutionQueue (existing — `src/GameBot.Domain/Queues/ExecutionQueue.cs`)

Fields copied verbatim from source to duplicate (all except `Id`, `Name`, `CreatedAt`, `UpdatedAt`):

| Field | Copied? | Notes |
|-------|---------|-------|
| `Id` | No | New value generated by `IQueueRepository.CreateAsync`, same as any new queue. |
| `Name` | No | Caller-supplied; MUST differ from source `Name` (validated). |
| `EmulatorSerial` | Yes | Required field on `ExecutionQueue`; copied as-is. |
| `CycleExecution` | Yes | |
| `PauseWhenIdle` | Yes | |
| `IdleThresholdSeconds` | Yes | Passed through `CoerceThreshold` for consistency with create/update, though the source value is already valid. |
| `EmulatorInstanceName` | Yes | Passed through `NormalizeInstanceName` for consistency. |
| `EmulatorInstanceIndex` | Yes | |
| `LinkedTemplateId` | Yes | Same template reference — no template copy. |
| `LinkedGameId` | Yes | Same game reference. |
| `CreatedAt` / `UpdatedAt` | No | Set fresh by the repository on create, same as any new queue. |

## Queue runtime state (existing — `IQueueRuntimeStore`)

Not part of `ExecutionQueue`; not persisted; scoped by queue ID.

| Aspect | Behavior for the duplicate |
|--------|------------------------------|
| Entries (`GetEntries`/`SetEntries`) | Copied: `SetEntries(newId, GetEntries(sourceId).Select(e => e.SequenceId))`. |
| Status (`GetStatus`) | Not copied — defaults to `Stopped` for a brand-new ID (nothing has started it yet). |
| Execution history / monitor state | Not copied — scoped to the source's own run history, which the duplicate has none of. |

## New request contract

`DuplicateQueueRequest` (`src/GameBot.Service/Contracts/Queues/DuplicateQueueRequest.cs`):

```csharp
public sealed class DuplicateQueueRequest {
  public string? Name { get; set; }
}
```

## Response contract

Reuses the existing `QueueResponse` (`src/GameBot.Service/Contracts/Queues/QueueResponse.cs`) — no
new response shape. The web-ui `QueueDto` type already models every field on it.

## Validation rules (endpoint-level, not a domain invariant)

1. `id` (route) must resolve to an existing `ExecutionQueue` — else `404 not_found`.
2. `Name` (body), trimmed, must be non-empty — else `400 invalid_request` ("name is required"),
   matching `CreateQueue`/`UpdateQueue`.
3. `Name` (body), trimmed, must not equal the source queue's `Name` (ordinal comparison) — else
   `400 invalid_request` ("name must differ from the original queue's name").
